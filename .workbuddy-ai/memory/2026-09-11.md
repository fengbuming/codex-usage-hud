## 排查：Codex UI 白屏（非锁屏场景）——根因不是 v1.2 回归（2026-09-11 16:40）

用户报告：Codex Desktop 最近频繁白屏，且不是锁屏后发生，怀疑 v1.2 之后某次提交导致 v1.1 锁屏修复回归。

结论：**不是 v1.2 回归**。
- v1.1 锁屏守卫链路自 v1.1.0 起零改动：`renderer_connection.py`、`session_activity.py`、`renderer_client.py`(quiesce/resume)、`renderer_event_loop.py` 在 `v1.1.0..HEAD` 均无提交；`git log v1.1.0..HEAD --` 这些文件为空。
- 真实根因是 **overlay helper 进程风暴**（预先存在的潜伏缺陷，非新引入），与锁屏无关。

证据（本机 `%LOCALAPPDATA%\codex-usage-hud\`）：
- `crash.log`：09-11 共 15084 次 HUD 进程启动；风暴窗口 09:21–09:30（~144/min）与 13:55–16:26（~150/min）。15:40 那一分钟 155 行 / 100 个不同 PID，间隔 ~0.37s（≈ Python+PySide6 冷启动耗时）。
- `daemon.log`：09-11 发生 7 次 daemon 重启（08:59/11:15/13:31/14:39/14:41/14:42/16:26）。
- `renderer_fallback.log`：09-10 17:56 `cdp.update_failed ConnectionResetError 10054` + `binding closed` → 自动 `restart-codex-for-renderer`；09-11 14:40、16:26 两次 `initial_connect_failed: TimeoutError`。
- `hud_settings.json`：`rest_reminder.enabled=true`，45min 间隔，工作窗口 09:00–18:00；`cycleStartedAtMs=1789115052716` → 2026-09-11 16:24:12，而 `crash.log` 16:24–16:26 正好爆发 231 次进程启动。**风暴与休息提醒气泡出现强相关。**

机制（已用最小复现验证）：
1. `renderer_event_loop._sample_rest_reminder()` 每个 renderer tick 都调用 `publish_rest_reminder(...)` → `DesktopWorkOverlay.update_rest_reminder(payload)`（`renderer_event_loop.py:177/284`）。
2. payload 非空且未变化时走 `desktop_overlay.py:269-285` 分支：`_ensure_helper_healthy()` → `if self._process is None: self._restart_blocked_until = 0.0`（**清零退避**）→ `if self._process is None and now >= 0: self._start()`（**无 keepalive 门控、无退避**）。`show_system_notice()`（340-342）同样无退避重启。
3. `overlay_supervision.evaluate_helper_health()` 把 `exit_code==0` 判为 `restart_blocked_until=0.0`（"干净退出立即可重启"）。
4. 复现脚本：FakeProc 立即退出（returncode=1），12 个 tick → **12 次进程拉起**，`_restart_blocked_until` 被写为 now+60 但完全被绕过。
5. 后果：~150 进程/分钟（每个含 PySide6 冷启动）→ CPU 饱和 → Codex 的 Chromium renderer 抢不到 CPU → 窗口空白 → HUD 侧 CDP 超时 → 触发自动重启 Codex。

引入时间（均早于 v1.1.0，故为潜伏缺陷）：
- `desktop_overlay.py` 零退避重启：c71c8f7 (2026-08-04)、51bbfae (2026-08-07)。
- `overlay_supervision.py` 干净退出=零退避：51bbfae (2026-08-07)。
- 每 tick 发布 rest reminder：c71c8f7 (2026-08-04)。

待修方向（未实施，待用户确认）：
- `update_rest_reminder` / `show_system_notice` 不得清零 `_restart_blocked_until`，且 `_start()` 前必须统一走"退避 + 连续失败熔断"门控；
- 给 overlay helper 增加**连续快速退出熔断**（如 N 秒内退出 M 次则进入指数退避/暂停），避免任何"立即退出"组合变成风暴；
- `evaluate_helper_health` 中 `exit_code==0` 也应保留最小退避（如 `max(1s, backoff/…)`）或由调用方统一限速。
