
## 跨项目排查：MSZS ScanClient 批扫断网后重试仍失败（2026-09-11 09:30）

> 说明：本次为对另一项目 `E:\Work\scan_project`（MSZS.ScanClient 扫描客户端）的日志+源码排查，非 codex-usage-hud 改动，记录备查。

- 现象：批量扫描页断网后扫描，识别不到学号；网络恢复后点「一键重试」仍失败。
- 日志来源：`\\172.16.1.123\...\ScanClient\Profiles\Staging\Logs`（Infos/AIUrlFailover、Infos/AiOcrSwitch、Infos/ApiRequestOcr、Infos/RoiRetry、Infos/RecognizeTiming、Errors）。
- 根因：AI OCR 故障转移是「单向 + 粘性」的，且用户重试不重置转移状态。
  1. 候选地址池（非生产）：`116.62.211.184:8441 → 121.41.4.57:8443 → u216305-9c1b-fcc1c7b0.westx.seetacloud.com:8443`（`AIUrlNonProductionDomains`，BaseService.cs:69）。失败只向后走，不回头。
  2. 断网时三跳全失败，每个失败地址记 5min 冷却（`AIUrlMainFailureCooldownMilliseconds=300000`），active 被钉在最后一个 seetacloud。
  3. 网络恢复后 `GetAvailableAIUrl` 在 `Unavailable && now < retryAfter` 期间直接返回 active（seetacloud），不会去试已恢复的主地址（AiOcrSwitchHelper.cs:97-100）。
  4. seetacloud 是「AI域名结果」地址，不提供 `/tool_merge_ZIP_LS_scanner_ocr(_student_name)` → 404。
  5. 404 触发 30min 长冷却（`LegacyStudentNameApiNotFoundCooldownMilliseconds=1800000`，09:31:37→10:01:37），期间 `ShouldSkipLegacyStudentNameApi` 直接短路，不发请求。
  6. 「一键重试」`OnRetryStudentRecognitionAsync`（EnhancedScanListPageViewModel.cs:5412）只探业务域名+重新入队，**不重置故障转移状态**；唯一重置入口 `ResetForTesting` 仅测试用。
- 修复方向：重试时强制重探/重置 failover；主地址冷却到期前的用户重试应允许立即重探高优先级地址；404 不应走 30min 惩罚性冷却；seetacloud 备用地址接口缺失需修正或移出候选池。

## codex-usage-hud：修复「供应商id/模型id」被当成新模型（2026-09-11 13:40）

现象（用户实测截图）：后台价格同步后，「官方模型价格」弹窗把同一模型按供应商拆成多行（`custom/gpt-5.4`、`dkby/gpt-5.4`、`hiyo/gpt-5.4`、`nexavlinks/…`、`token-x/…`），并提示「官方快照暂未收录 38 个本地模型」。实测配置：`price_table()` = 6 个裸键 + 35 个 `provider/model` 复合键 = 41；`pending_prices` 42 行、`pending_changes` 里 38 条 `removed`。

根因：`runtime_context._pricing_check` 直接把 `UserConfig.price_table()` 交给比对，而 `price_table()` 用 `f"{provider}/{name}"` 作键；`merge_pricing_rows` 又拿**字典键**当 `model` 输出，于是复合键泄漏到 UI，且 `classify_price_changes` 用 `local.get(official_model)` 永远匹配不上 → 全部记为 `removed`。

修复：
- `pricing_sync.py`：新增 `_bare_model_id()`（`rpartition("/")` 取尾段，与 `ModelPrice.from_mapping` 既有约定一致）与 `normalize_local_price_scope(table, preferred_provider=)`，按裸模型 id 折叠去重，优先级 = 活动供应商 > 无 provider 的旧全局行 > 表内顺序，键 casefold；`classify_price_changes` 改为 casefold 查找/归属判断。
- `runtime_context.py`：`_pricing_check` 改用 `normalize_local_price_scope(..., preferred_provider=context.app_provider)`，`extra_model_ids` 也随之变成裸 id。
- `settings_shell.py`（渲染层兜底，让**已持久化的旧缓存**也立刻显示正确）：`normalizePriceModel` 去掉 `provider/` 前缀；新增 `pricingBareModelId()`、`pricingCachedRows()`；`pricingCachedPreview` 按裸 id 折叠 `pending_prices`（按 model）与 `pending_changes`（按 model|field|kind），并丢弃「与同一 payload 中 official 行矛盾」的 `removed` 条目；`changeCount` 改为排除 `removed`（与后端 `len(applied_changes)` 语义对齐）。
- 新增回归用例：`tests/test_pricing_sync.py::test_normalize_local_price_scope_folds_provider_scoped_duplicates`、`tests/test_renderer_hud.py::test_pricing_scope_folds_to_one_row_per_model`。

验证结果（用户真实配置）：41 → 7 个模型（4 官方 + `gpt-5.4` / `gpt-5.4-mini` / `gpt-5.5` 三个官方未收录），真实差异 1 项（`gpt-6-astra` input 11 → 10）。测试：`test_renderer_hud.py` 111 项、聚焦集 52 项全绿；另用 Node 抽取真实函数体对**真实历史缓存**跑 16 项断言全绿。

遗留（已知，未处理）：①用户配置里已持久化的旧 `pending_prices/pending_changes` 是脏派生缓存，弹窗的「差异 N」计数仍是旧值（6），点弹窗内「重新获取」或等下一次后台同步即刷新为 1；②`applyPricingSync`（对应 `pricing-sync-open` 动作）在 UI 上**不可达**（无任何 markup 触发），其内部仍按旧复合键落盘，若将来接线需一并规范化。

## codex-usage-hud：价格比较只针对默认(App)供应商 + 确认更新后界面即时刷新（2026-09-11 14:46）

用户口径（经三轮澄清确认）：**价格比较与写入都只针对默认(App)供应商，其它供应商完全不参与**；写入目标保持现状（只写 App 供应商）。

实测确认的现状：`确认更新` 端到端跑通（`pricingImportCommit` → `apply_pricing_import` + `_sync_imported_current_prices`），只写 App 供应商（本机 `custom`），其它 4 个供应商不动，`unread_change_count` 归零。

改动：
- `runtime_context.py`：`_pricing_check` 的比较源由 `normalize_local_price_scope(price_table(), preferred_provider=app_provider)` 收紧为 `normalize_local_price_scope(provider_price_table(app_provider))` —— 非默认供应商不再作为兜底参与比较；无默认供应商时仍回退旧全局 `model_prices`（`provider_price_table("")` 自带该回退）。对本机数据结果不变（custom 已覆盖全部模型）。
- `settings_shell.py`：`applyPricingCommandStatus` 新增 `pricingImportCommit` 成功分支 —— 关闭价格弹窗 + `renderSettingsProviderEditor()` 重绘单价表 + `syncPricingApplyDirtyState()` + `syncPricingUnreadIndicators()`。**当前供应商若有未保存单价草稿则跳过重绘**（避免覆盖用户编辑）；错误分支在它之前 return，弹窗保留以便重试。修复了「点了确认更新，弹窗不关、单价表还是旧值 → 看起来没生效」。
- 新增回归用例：`tests/test_pricing_sync.py::test_default_provider_scope_excludes_other_providers_prices`、`tests/test_renderer_hud.py::test_pricing_commit_refreshes_dialog_and_price_table`。
